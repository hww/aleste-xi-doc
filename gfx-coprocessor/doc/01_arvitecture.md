# Графический сопроцессор для Z80: обзор архитектуры

*Черновик для обсуждения. Это не спецификация, а карта местности: что за блоки, как они связаны, что каждый делает. Цифры ориентировочные.*

## 1. Принципы

1. **Простота важнее пиковой скорости.** Узкое место всё равно память (около 27 МБ/с), поэтому ядро можно делать простым, лишь бы оно укладывалось в 8 тактов на пиксель.
2. **Ядро программируемое, а не жёстко-автоматное.** Регистровый файл в BRAM, один DSP, микропрограмма. Новый алгоритм означает новый микрокод, а не новую логику (нет комбинаторного взрыва).
3. **В железо выносится только горячий путь:** буферы слова и узкий комбайнер.
4. **Экранные координаты внутри, адреса снаружи не видны.** CPU говорит «нарисуй в (x, y)», а не «в адрес такой-то».
5. **Два формата пикселя: 4 и 8 bpp.** Формат 1 bpp допустим только как источник (шрифты, маски).
6. **Никакого аппаратного скроллинга.** Вместо него быстрое копирование блоков.
7. **Команды как записи в регистры:** RISC-стиль, всё тривиально по интерпретации.

## 2. Общая картина

![Архитектура микроядра](../images/lx-gpu-architecture.webp)

*Где проходит граница доменов: **вся логика команд и регистров живёт в 8-битном домене**, где её проще минимизировать. **Ядро, буферы слов и видеоконтроллер** обращаются к памяти по 16 битам. Ядро по сути «мастер» на 16-битной шине, а в 8-битном домене оно видно только как набор регистров.*

*Пересечение доменов делается в одном месте: **регистры ядра**. CPU пишет туда по 8 бит, ядро читает по 24 бита.*

Особенность системы в том, что CPU записывает регистры GPU только через командный интерфейс. Но может прочитывать статус через прямой доступ к регистру. Также командный интерфейс не работает с регистрами палитры.

## 3. Блоки по порядку

### 3.1 Интерфейс к CPU

Четыре порта ввода-вывода (примерно):

| Порт | Назначение |
| --- | --- |
| CMD | запись в FIFO команд, 3 байта на команду |
| STATUS | чтение: FIFO заполнено, ядро занято, номер строки |
| VRAM | окно в видеопамять с автоинкрементом (для загрузки данных) |

Команда уходит блоком `OTIR`: три байта на запись, примерно 50 мкс на пять-шесть команд. Если FIFO заполнено, выставляется `/WAIT` и CPU ждёт без опроса статуса.

### 3.2 FIFO и декодер команд

FIFO в BRAM, 16-1024 записей по 3 байта. Декодер берёт код команды и либо записывает операнд в регистр ядра, либо запускает микропрограмму. Пока ядро занято, команда, зависящая от результата, ждёт. Проще всего: **FIFO просто выдаёт команды по очереди, и `EXEC` блокирует выдачу до конца операции**.


### 3.3 Ядро

Микропрограммный автомат типа «маленький процессор»:

- **Регистровый файл** 32-64 слова по 24 бита (BRAM, два порта чтения).
- **АЛУ + один DSP-блок:** сложение, вычитание, сдвиги, сравнение, умножение 12×12.
- **Память микрокода** 256-512 слов, загружается процессором при старте.
- **Счётчики и переходы:** условия по знаку, нулю, переносу. Одна команда «цикл».

### 3.4 Конвертер координат в адрес

Единственная точка, где вообще появляется адрес. Для линейного индекса `idx = y*stride + x`:

```
4 bpp:  слово = base + idx>>2,   пиксель в слове = idx[1:0]
8 bpp:  слово = base + idx>>1,   пиксель в слове = idx[0]
```

Умножение на каждый пиксель нужно только для аффинного режима и линий. Для прямоугольников микрокод считает индекс **один раз на строку**, а дальше просто делает `idx++`. Это оптимизация микрокода, а не железа.

### 3.5 Буферы слова

Память 16-битная, а ядро работает по одному пикселю, поэтому нужны два буфера:

- **Буфер источника:** держит последнее прочитанное слово.
- **Буфер приёмника:** держит слово, в котором меняем пиксели. Флаг «грязное».

Чтобы ядро не простаивало, чтение следующего слова запускается заранее.

### 3.6 Комбайнер

Узкий блок на пути данных: берёт пиксель источника, пиксель приёмника и регистры, выдаёт результат. 

В 4 bpp работает младшая тетрада, остальное маскируется. Таблица (LUT) не используется: в 8 bpp она слишком велика, а набор фиксированных операций работает в обоих режимах.

### 3.7 Источник: форматы 1, 4, 8 bpp

Канал источника имеет поле `S_FMT`:

| Формат | Читаем | Пиксель |
| --- | --- | --- |
| 8 bpp | байт | байт целиком |
| 4 bpp | тетрада | 4 бита |
| 1 bpp | бит | `бит ? FG : BG`, BG может быть «прозрачным» |

Это всё: stencil не отдельное устройство, а способ интерпретации слова. Одним и тем же приёмом получается рисование шрифтов и рисование контура через маску.

### 3.8 Клиппинг

Четыре регистра CX0, CY0, CX1, CY1 (знаковые 12 бит). Работа:

1. Перед циклом по строкам микрокод проверяет Y; строки вне окна пропускаются.
2. Для строки один раз обрезается диапазон X (начало и конец), цикл идёт только по видимому.
3. В аффинном режиме и в линиях проверка идёт на пиксель, а в прямоугольниках бесплатно.

### 3.9 Видеоконтроллер и палитра

Видеоконтроллер читает пакетами из памяти и отдаёт пиксели на палитру. Палитра лежит в 8-битном домене. Развёртка имеет **высший приоритет** в арбитре памяти.

## 4. Команды

Формат: **1 байт код + 16 бит операнд = 3 байта**. Любое 24-битное значение записывается двумя командами (`LO`, `HI`).

Запуск: команда `EXEC` блокирует выдачу следующих команд до конца операции.

### Диспетчеризация

| --- | --- | --- | --- | --- |
| 0x00-0x1F | **SET16** | — | — | Write FIFO16S into R0-R31 |
| 0x20-0x3F | **SET8** | — | — | Write FIFO8 into R0-R31 |

**Пример: нарисовать спрайт 16×16 с прозрачностью** (после одного раза настройки базы, строки и ключа):

```
SET_SX, SET_SY      ; откуда
SET_DX, SET_DY      ; куда
SET_W (=16), SET_H (=16)
EXEC  PROG_COPY
```

Пять-шесть команд, всё в одном `OTIR`.

## 5. Микрокод: как это выглядит

Микрослово (набросок, 24-32 бита): `[операция АЛУ | источник A | источник B | приёмник | управление памятью | переход]`.

![Формат микрослова](../output/microinstruction.svg)

Псевдокод микропрограммы **заливки прямоугольника** (без аффинных шагов):

```
PROG_FILL:
    clip_rect()                      ; обрезать DX, DY, W, H окном
    if W <= 0 or H <= 0: goto DONE
    row = H
ROW:
    idx = DY * D_STRIDE + DX         ; DSP: один раз на строку
    cnt = W
PIX:
    waddr, sub = split(idx)
    if waddr != cached_waddr:        ; смена слова
        flush_dst()
        dst_read(waddr)
    dst_word[sub] = combine(FG, dst_word[sub])
    idx++ ; cnt--
    if cnt != 0: goto PIX
    DY++ ; row--
    if row != 0: goto ROW
    flush_dst()
DONE: halt
```

В цикле `PIX` около 5-6 микроопераций. Это укладывается в бюджет 8 тактов на пиксель.

**Копирование спрайта** отличается добавлением второго индекса. **Аффинная версия:** индекс источника считается на каждый пиксель. **Линия (Bresenham):** сумматор ошибки плюс два шага, без умножения.

| Z80 без помощи | 0,1-0,2 Мпикс/с |

Вывод: при таких цифрах ядро и память примерно сбалансированы. Доводить ядро до 1 такта на пиксель не имеет смысла.

## 7. Что мы осознанно не делаем

- Аппаратный скроллинг и page flip как обязательная вещь.
- LUT цвет×цвет.
- Форматы 2 и 3 bpp.
- Третий источник (заменяется двумя проходами через скрытую страницу).

## Принятые решения

- **Регистровый файл ядра:** 32 слова.
- **Микрокод в RAM (BRAM), не в ROM.** RAM дешевле и позволяет менять алгоритмы.
- **Порядок пикселей:** в байте первым (левым) идёт старшая тетрада.
- **Прозрачность:** цвет 0 источника никогда не пишется.
- **Комбайнер в два уровня.** Базовый: copy, AND, OR, XOR, сложение и вычитание с насыщением. Продвинутый: смешивание со сдвигом.
- **Запуск:** отдельная команда `EXEC`.
- **Переполнение FIFO:** шина просто не выдаёт ACK, пока в FIFO нет места.
- **Режим 8 bpp:** только 320×200.

# Микроядро графического сопроцессора

Ядро — единственный «процессор» внутри сопроцессора: оно само вынимает байты команд из FIFO, разбирает их микрокодом и рисует. Отдельного декодера и отдельного пути записи регистров нет.

## 1. Главная идея

- Z80 пишет в один порт, байты попадают в FIFO. Кроме него у CPU есть только аппаратный порт статуса (FIFO заполнено, ядро простаивает, ядро в ошибке).
- Главный цикл микропрограммы: взять байт-опкод, перейти по таблице, выполнить обработчик, вернуться. Если FIFO пуст, ядро ждёт на первой же микрокоманде. По этому простою выставляются флаг готовности и прерывание.
- Отдельной команды запуска нет: команда `FILL` сама и есть вызов подпрограммы. Закончилась — ядро вернулось в главный цикл.
- Опкод меньше 32 означает «записать 16 бит в регистр Rn». Регистровый файл и есть набор команд установки параметров.
- Команды бывают переменной длины, блоки данных читаются тем же способом. Для `OTIR` границы команд безразличны.
- Запись в регистр статуса может быть использована для soft reset (не обязательно).

## 5. Микрослово и конвейер

Микрослово 36 бит (ширина BRAM ×36 у Cyclone IV и ECP5), 512 слов:

![Формат микрослова](../output/microinstruction.svg)

Условия перехода:

- 0: нет
- 1: всегда
- 2: Z (ноль)
- 3: NZ (не ноль)
- 4: N (отрицательное)
- 5: не N
- 6: CALL
- 7: RET
- 8: JMPI (адрес = X + значение SA)
- 9: FIFO пуст

Хватает одного регистра возврата без вложенности.

АЛУ и переход в одном слове: `T1 = SUB(T1, 1); JNZ PIX` занимает одну микрокоманду.

Конвейер двухступенчатый: выборка слова из BRAM, затем чтение операндов, АЛУ, запись и решение о переходе. Невзятый переход бесплатен, взятый стоит один лишний такт. Любое обращение к SPIX, DPIX, FIFO8 или FIFO16, которое не готово, замораживает весь конвейер одним сигналом.

- биты 2:1 SFMT: 0 = 4 bpp, 1 = 8 bpp, 2 = 1 bpp;
- биты 5:3 COP: 0 копия, 1 AND, 2 OR, 3 XOR, 4 ADD с насыщением, 5 SUB с насыщением;
- бит 6 TR: если включён и пиксель источника равен 0, результат равен B (прозрачность).

Так «прозрачный» пиксель возвращает приёмник без изменений, и не нужен ни отдельный флаг, ни условный пропуск записи.

## 7. Блок памяти

Он реализует прежнюю идею «пиксель за пикселем» и скрывает слово 16 бит от микрокода.

- Запись `DIDX = idx` задаёт линейный индекс пикселя. Блок сам берёт DBASE, формат и считает адрес слова и номер пикселя в нём (4 bpp: 4 пикселя в слове, 8 bpp: 2, 1 bpp: 16).
- Если слово сменилось: грязное слово сначала записывается, затем читается новое. Чтение запускается сразу, а ядро замораживается лишь при обращении к DPIX. Поэтому между `DIDX` и `DPIX` можно ставить другие микрокоманды, и задержка памяти перекрывается с расчётом.
- То же для `SIDX` и `SPIX`. В формате 1 bpp SPIX возвращает FG для единичного бита и BG для нулевого. BG = 0 даёт прозрачный фон.
- Запись в `DPIX` меняет только нужную тетраду или байт в DW. Флаг dirty ставится лишь если значение изменилось.
- Правило согласованности: если слово источника уже лежит в DW, SW берёт его оттуда, а не из памяти. Иначе перекрывающееся копирование читает устаревшие данные. Направление цикла выбирает микрокод, сравнивая индексы.
- `FLUSH` обязателен в конце каждой рисующей подпрограммы.

В 4 bpp запись всегда читает слово заранее (маска записи на шине работает по байтам, не по тетрадам). В 8 bpp непрозрачную запись можно выполнять без чтения, это отдельная оптимизация.

## 8. Главный цикл и команды

```
; адреса 0..31   : SET16 Rn   Rn = FIFO16S ; JMP MAIN
; адреса 32..63  : SET8  Rn   Rn = FIFO8   ; JMP MAIN
; адреса 64..127 : остальные команды (по одной микрокоманде-переходу)
;   0x40 NOP  0x41 FILL  0x42 COPY  0x43 STENCIL  0x44 LINE
;   0x45 AFFINE  0x46 PAL  0x47 LOAD  0x48 IRQ  0x49 GET

MAIN:  JMPI FIFO8, X=0       ; взять опкод, перейти на адрес = опкод
```

Обработчик установки регистра занимает одну микрокоманду. Прием команды `SET16` стоит около 4 тактов (2 на чтение байтов, 1 на `MAIN`, 1 на переход). Программы рисования начинаются с адреса 128.

`PAL idx, color` пишет в PALI и PALD. `LOAD n` берёт n байт из FIFO и пишет их в видеопамять подряд, так загружаются спрайты. `IRQ` пишет в STAT и выставляет прерывание, когда все предыдущие команды выполнены. `GET Rn` копирует регистр в защёлку, доступную на аппаратном порту чтения (нужна для чтения пикселя и проверки столкновений).

## 9. Примеры

**Заливка прямоугольника**, X-клиппинг в начале (Y-клиппинг делается так же через MAX/MIN, опущен):

![Алгоритм заливки](../output/algorithms.svg)

```
FILL:  T2 = MOV(H)
       T5 = MOV(DY)
       T3 = MAX(DX, CX0)          ; x0
       T4 = ADD(DX, W)
       T4 = MIN(T4, CX1)          ; x1
       T4 = SUB(T4, T3) ; JN DONE ; ширина после отсечения
ROW:   T0 = MUL(T5, DSTRIDE)
       T0 = ADD(P, T3)            ; индекс = Y*stride + x0
       T1 = MOV(T4)
PIX:   DIDX = MOV(T0)
       DPIX = COMB(FG, DPIX)
       T0 = ADD(T0, 1)
       T1 = SUB(T1, 1) ; JNZ PIX
       T5 = ADD(T5, 1)
       T2 = SUB(T2, 1) ; JNZ ROW
DONE:  FLUSH = MOV(ZERO) ; JMP MAIN
```

**Копирование с прозрачностью.** Внутренний цикл:

![Алгоритм копирования](../output/algorithms.svg)

```
PIX:   SIDX = MOV(T6)
       DIDX = MOV(T0)
       DPIX = COMB(SPIX, DPIX)
       T6 = ADD(T6, 1)
       T0 = ADD(T0, 1)
       T1 = SUB(T1, 1) ; JNZ PIX
```

Цикл заливки занимает 4 слова, копирования 6 слов, плюс по такту на взятый переход: 5 и 7 тактов на пиксель без учёта ожиданий памяти. Ожидание добавляет около 2 тактов на пиксель в 4 bpp, поэтому реальная скорость порядка 6–9 тактов на пиксель (оценка, не расчёт). Если переходы сильно мешают, индексы SIDX и DIDX можно сделать счётчиками с автоинкрементом при обращении к SPIX и DPIX. Тогда копирование сводится к трём словам.

**Аффинный режим** — тот же цикл, но индекс источника считается каждый раз: `u += STA; v += STC; sidx = (v >> 12) * SSTRIDE + (u >> 12)` (SHR, MUL, ADD). Это 6–7 микрокоманд на пиксель.

## 10. Узкие места и роль FIFO

FIFO нужен не для корректности, а для параллелизма. Без него каждая запись Z80 ждала бы, пока ядро закончит рисование. С ним CPU кладёт в очередь десятки команд и занимается своими делами.

По порядку величин (Z80 3,5 МГц, `OTIR` около 6 мкс на байт):

- спрайт 16×16: около 256 × 8 тактов при 108 МГц, то есть примерно 20 мкс;
- команда из 6 байт: около 36 мкс.

Для мелких объектов узким местом оказывается подача команд, а не ядро. Из этого следует практика: менять только изменившиеся регистры, держать часто повторяющиеся параметры в регистрах, а для больших партий спрайтов позже добавить команду, читающую параметры из списка в видеопамяти.

Байты FIFO берутся прямо из шины, поэтому FIFO достаточно мелкого: 64–256 байт в одном блоке BRAM.

Исключение из принципа «один интерфейс» неизбежно одно: **загрузка микрокода**. Ядро не может исполнять программу, которой у него ещё нет, поэтому BRAM инициализируется из прошивки, а для замены есть аппаратный порт: ядро останавливается, процессор записывает по 5 байт на слово, ядро запускается.

## 11. Открытые вопросы

1. **Время условия перехода:** флаг и решение о переходе стоят в одной ступени. На 108 МГц на Cyclone IV это может не уложиться. Запасной вариант — использовать флаги предыдущей микрокоманды, тогда цикл станет на слово длиннее.
2. **Автоинкремент индексов** SIDX и DIDX: делаем сразу или оставляем на потом.
3. **Ширина тракта:** 24 бита нужны для аффинных шагов (12.12). Для остальных операций хватило бы 16, но разделять тракт нет смысла.
4. **Умножитель:** 12×12 хватает для `Y*stride` и аффинных адресов. Нужна ли ширина 18×18 для других задач?
5. **Палитра:** запись из ядра пересекает границу тактовых доменов, если видеоконтроллер работает на другой частоте.
6. **Быстрая заливка по слову** (4 пикселя за раз): отдельная подпрограмма, нужна ли в первой версии.
7. **Список в видеопамяти:** нужна ли возможность читать команды не только из FIFO, но и из ОЗУ.
