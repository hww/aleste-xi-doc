# Микроядро графического сопроцессора

Ядро — единственный «процессор» внутри сопроцессора: оно само вынимает байты команд из FIFO, разбирает их микрокодом и рисует. Отдельного декодера и отдельного пути записи регистров нет.

## 1. Главная идея

- Z80 пишет в один порт, байты попадают в FIFO. Кроме него у CPU есть только аппаратный порт статуса (FIFO заполнено, ядро простаивает, ядро в ошибке).
- Главный цикл микропрограммы: взять байт-опкод, перейти по таблице, выполнить обработчик, вернуться. Если FIFO пуст, ядро ждёт на первой же микрокоманде. По этому простою выставляются флаг готовности и прерывание.
- Отдельной команды запуска нет: команда `FILL` сама и есть вызов подпрограммы. Закончилась — ядро вернулось в главный цикл.
- Опкод меньше 32 означает «записать 16 бит в регистр Rn». Регистровый файл и есть набор команд установки параметров.
- Команды бывают переменной длины, блоки данных читаются тем же способом. Для `OTIR` границы команд безразличны.
- Запись в регистр статуса может быть использована для soft reset (не обязательно).

## 3. Операнды

Каждое поле операнда в микрослове — 6 бит. Одни и те же адреса дают и регистры, и «окна» в аппаратуру, поэтому спецоперации не требуют отдельных команд.

| Адрес | Имя | Чтение | Запись |
| --- | --- | --- | --- |
| 0-31 | **R0-R31** | 24-bit register file | 24-bit register file |
| 32 | **ZERO** | Constant zero | Ignored |
| 33 | **ACC** | Previous ALU result | Not writable |
| 34 | **P** | Multiplier result | Not writable |
| 35 | **FIFO8** | Pop one byte; wait while empty | Not writable |
| 36 | **FIFO16** | Pop two bytes, low byte first | Not writable |
| 37 | **FIFO16S** | Pop two bytes, sign-extended | Not writable |
| 38 | **SPIX** | Source pixel from SW | Not writable |
| 39 | **DPIX** | Destination pixel from DW | Write pixel to DW, mark dirty |
| 40 | **SIDX** | Not readable | Set source linear pixel index |
| 41 | **DIDX** | Not readable | Set destination linear pixel index |
| 42 | **FLUSH** | Not readable | Flush dirty destination word |
| 43 | **PALI** | Not readable | Palette index |
| 44 | **PALD** | Not readable | Palette colour |
| 45 | **IMM** | 9-bit immediate from X field | Not writable |
| 46 | **STAT** | Status flags | Request interrupt |


Модель трёхадресная (`DST = OP(A, B)`), поэтому один аккумулятор не становится бутылочным горлышком. ACC нужен лишь как бесплатный источник результата следующей микрокоманды.

## 5. Микрослово и конвейер

Микрослово 36 бит (ширина BRAM ×36 у Cyclone IV и ECP5), 512 слов:

![Формат микрослова](../output/microinstruction.svg)

Условия перехода:

- 0: нет
- 1: всегда
- 2: Z (ноль)
- 3: NZ (не ноль)
- 4: N (отрицательное)
- 5: не N
- 6: CALL
- 7: RET
- 8: JMPI (адрес = X + значение SA)
- 9: FIFO пуст

Хватает одного регистра возврата без вложенности.

АЛУ и переход в одном слове: `T1 = SUB(T1, 1); JNZ PIX` занимает одну микрокоманду.

Конвейер двухступенчатый: выборка слова из BRAM, затем чтение операндов, АЛУ, запись и решение о переходе. Невзятый переход бесплатен, взятый стоит один лишний такт. Любое обращение к SPIX, DPIX, FIFO8 или FIFO16, которое не готово, замораживает весь конвейер одним сигналом.

## 6. Операции АЛУ

| Код | Имя | Действие |
| --- | --- | --- |
| 0 | **MOV** | A |
| 1 | **ADD** | 24-bit addition; updates Z and N |
| 2 | **SUB** | 24-bit subtraction; updates Z and N |
| 3 | **AND** | Bitwise AND |
| 4 | **OR** | Bitwise OR |
| 5 | **XOR** | Bitwise XOR |
| 6 | **SHL** | Shift left by B[4:0] |
| 7 | **SHR** | Logical shift right by B[4:0] |
| 8 | **SAR** | Arithmetic shift right by B[4:0] |
| 9 | **MIN** | Signed minimum |
| 10 | **MAX** | Signed maximum |
| 11 | **MUL** | A[11:0] × B[11:0] → P |
| 12 | **ADDS** | Saturating addition |
| 13 | **SUBS** | Saturating subtraction |
| 14 | **COMB** | Pixel combine controlled by MODE |


`COMB(A = пиксель источника, B = пиксель приёмника)` управляется регистром MODE:

![Регистр MODE](../output/mode_register.svg)

- бит 0 DFMT: 0 = 4 bpp, 1 = 8 bpp;
- биты 2:1 SFMT: 0 = 4 bpp, 1 = 8 bpp, 2 = 1 bpp;
- биты 5:3 COP: 0 копия, 1 AND, 2 OR, 3 XOR, 4 ADD с насыщением, 5 SUB с насыщением;
- бит 6 TR: если включён и пиксель источника равен 0, результат равен B (прозрачность).

Так «прозрачный» пиксель возвращает приёмник без изменений, и не нужен ни отдельный флаг, ни условный пропуск записи.

## 7. Блок памяти

Он реализует прежнюю идею «пиксель за пикселем» и скрывает слово 16 бит от микрокода.

- Запись `DIDX = idx` задаёт линейный индекс пикселя. Блок сам берёт DBASE, формат и считает адрес слова и номер пикселя в нём (4 bpp: 4 пикселя в слове, 8 bpp: 2, 1 bpp: 16).
- Если слово сменилось: грязное слово сначала записывается, затем читается новое. Чтение запускается сразу, а ядро замораживается лишь при обращении к DPIX. Поэтому между `DIDX` и `DPIX` можно ставить другие микрокоманды, и задержка памяти перекрывается с расчётом.
- То же для `SIDX` и `SPIX`. В формате 1 bpp SPIX возвращает FG для единичного бита и BG для нулевого. BG = 0 даёт прозрачный фон.
- Запись в `DPIX` меняет только нужную тетраду или байт в DW. Флаг dirty ставится лишь если значение изменилось.
- Правило согласованности: если слово источника уже лежит в DW, SW берёт его оттуда, а не из памяти. Иначе перекрывающееся копирование читает устаревшие данные. Направление цикла выбирает микрокод, сравнивая индексы.
- `FLUSH` обязателен в конце каждой рисующей подпрограммы.

В 4 bpp запись всегда читает слово заранее (маска записи на шине работает по байтам, не по тетрадам). В 8 bpp непрозрачную запись можно выполнять без чтения, это отдельная оптимизация.

## 8. Главный цикл и команды

```
; адреса 0..31   : SET16 Rn   Rn = FIFO16S ; JMP MAIN
; адреса 32..63  : SET8  Rn   Rn = FIFO8   ; JMP MAIN
; адреса 64..127 : остальные команды (по одной микрокоманде-переходу)
;   0x40 NOP  0x41 FILL  0x42 COPY  0x43 STENCIL  0x44 LINE
;   0x45 AFFINE  0x46 PAL  0x47 LOAD  0x48 IRQ  0x49 GET

MAIN:  JMPI FIFO8, X=0       ; взять опкод, перейти на адрес = опкод
```

Обработчик установки регистра занимает одну микрокоманду. Прием команды `SET16` стоит около 4 тактов (2 на чтение байтов, 1 на `MAIN`, 1 на переход). Программы рисования начинаются с адреса 128.

`PAL idx, color` пишет в PALI и PALD. `LOAD n` берёт n байт из FIFO и пишет их в видеопамять подряд, так загружаются спрайты. `IRQ` пишет в STAT и выставляет прерывание, когда все предыдущие команды выполнены. `GET Rn` копирует регистр в защёлку, доступную на аппаратном порту чтения (нужна для чтения пикселя и проверки столкновений).

## 9. Примеры

**Заливка прямоугольника**, X-клиппинг в начале (Y-клиппинг делается так же через MAX/MIN, опущен):

![Алгоритм заливки](../output/algorithms.svg)

```
FILL:  T2 = MOV(H)
       T5 = MOV(DY)
       T3 = MAX(DX, CX0)          ; x0
       T4 = ADD(DX, W)
       T4 = MIN(T4, CX1)          ; x1
       T4 = SUB(T4, T3) ; JN DONE ; ширина после отсечения
ROW:   T0 = MUL(T5, DSTRIDE)
       T0 = ADD(P, T3)            ; индекс = Y*stride + x0
       T1 = MOV(T4)
PIX:   DIDX = MOV(T0)
       DPIX = COMB(FG, DPIX)
       T0 = ADD(T0, 1)
       T1 = SUB(T1, 1) ; JNZ PIX
       T5 = ADD(T5, 1)
       T2 = SUB(T2, 1) ; JNZ ROW
DONE:  FLUSH = MOV(ZERO) ; JMP MAIN
```

**Копирование с прозрачностью.** Внутренний цикл:

![Алгоритм копирования](../output/algorithms.svg)

```
PIX:   SIDX = MOV(T6)
       DIDX = MOV(T0)
       DPIX = COMB(SPIX, DPIX)
       T6 = ADD(T6, 1)
       T0 = ADD(T0, 1)
       T1 = SUB(T1, 1) ; JNZ PIX
```

Цикл заливки занимает 4 слова, копирования 6 слов, плюс по такту на взятый переход: 5 и 7 тактов на пиксель без учёта ожиданий памяти. Ожидание добавляет около 2 тактов на пиксель в 4 bpp, поэтому реальная скорость порядка 6–9 тактов на пиксель (оценка, не расчёт). Если переходы сильно мешают, индексы SIDX и DIDX можно сделать счётчиками с автоинкрементом при обращении к SPIX и DPIX. Тогда копирование сводится к трём словам.

**Аффинный режим** — тот же цикл, но индекс источника считается каждый раз: `u += STA; v += STC; sidx = (v >> 12) * SSTRIDE + (u >> 12)` (SHR, MUL, ADD). Это 6–7 микрокоманд на пиксель.

## 10. Узкие места и роль FIFO

FIFO нужен не для корректности, а для параллелизма. Без него каждая запись Z80 ждала бы, пока ядро закончит рисование. С ним CPU кладёт в очередь десятки команд и занимается своими делами.

По порядку величин (Z80 3,5 МГц, `OTIR` около 6 мкс на байт):

- спрайт 16×16: около 256 × 8 тактов при 108 МГц, то есть примерно 20 мкс;
- команда из 6 байт: около 36 мкс.

Для мелких объектов узким местом оказывается подача команд, а не ядро. Из этого следует практика: менять только изменившиеся регистры, держать часто повторяющиеся параметры в регистрах, а для больших партий спрайтов позже добавить команду, читающую параметры из списка в видеопамяти.

Байты FIFO берутся прямо из шины, поэтому FIFO достаточно мелкого: 64–256 байт в одном блоке BRAM.

Исключение из принципа «один интерфейс» неизбежно одно: **загрузка микрокода**. Ядро не может исполнять программу, которой у него ещё нет, поэтому BRAM инициализируется из прошивки, а для замены есть аппаратный порт: ядро останавливается, процессор записывает по 5 байт на слово, ядро запускается.

## 11. Открытые вопросы

1. **Время условия перехода:** флаг и решение о переходе стоят в одной ступени. На 108 МГц на Cyclone IV это может не уложиться. Запасной вариант — использовать флаги предыдущей микрокоманды, тогда цикл станет на слово длиннее.
2. **Автоинкремент индексов** SIDX и DIDX: делаем сразу или оставляем на потом.
3. **Ширина тракта:** 24 бита нужны для аффинных шагов (12.12). Для остальных операций хватило бы 16, но разделять тракт нет смысла.
4. **Умножитель:** 12×12 хватает для `Y*stride` и аффинных адресов. Нужна ли ширина 18×18 для других задач?
5. **Палитра:** запись из ядра пересекает границу тактовых доменов, если видеоконтроллер работает на другой частоте.
6. **Быстрая заливка по слову** (4 пикселя за раз): отдельная подпрограмма, нужна ли в первой версии.
7. **Список в видеопамяти:** нужна ли возможность читать команды не только из FIFO, но и из ОЗУ.
