# Графический сопроцессор для Z80: обзор архитектуры

*Черновик для обсуждения. Это не спецификация, а карта местности: что за блоки, как они связаны, что каждый делает. Цифры ориентировочные.*

## 1. Принципы

1. **Простота важнее пиковой скорости.** Узкое место — память, поэтому ядро можно делать простым.
2. **Ядро программируемое, а не жёстко-автоматное.** Регистровый файл в BRAM, один DSP, микропрограмма. Новый алгоритм — новый микрокод, а не новая логика.
3. **В железо выносится только горячий путь:** буферы слова и узкий комбайнер.
4. **Экранные координаты внутри, адреса снаружи не видны.** CPU говорит «нарисуй в (x, y)», а не «в адрес такой-то».
5. **Два формата пикселя: 4 и 8 bpp.** Формат 1 bpp допустим только как источник (шрифты, маски).
6. **Никакого аппаратного скроллинга.** Вместо него быстрое копирование блоков.
7. **Команды как записи в регистры:** RISC-стиль, всё тривиально по интерпретации.

## 2. Общая картина

![Архитектура микроядра](../images/lx-gpu-architecture.webp)

*Где проходит граница доменов: **вся логика команд и регистров живёт в 8-битном домене**, где её проще минимизировать. **Ядро, буферы слов и видеоконтроллер** обращаются к памяти по 16 битам. Ядро по сути «мастер» на 16-битной шине, а в 8-битном домене оно видно только как набор регистров.*

*Пересечение доменов делается в одном месте: **регистры ядра**. CPU пишет туда по 8 бит, ядро читает по 24 бита.*

CPU записывает регистры GPU только через командный интерфейс. Статус читается прямым доступом к регистру. Командный интерфейс не работает с регистрами палитры.

## 3. Блоки по порядку

### 3.1 Интерфейс к CPU

Четыре порта ввода-вывода:

| Порт | Назначение |
| --- | --- |
| CMD | запись в FIFO команд |
| STATUS | чтение: FIFO заполнено, ядро занято, номер строки |
| PAL | запись палитры (индекс, затем цвет) |
| VRAM | окно в видеопамять с автоинкрементом |

Команда уходит блоком `OTIR`. Если FIFO заполнено, выставляется `/WAIT`, и CPU ждёт без опроса статуса.

### 3.2 FIFO и FSM входного протокола

FIFO в BRAM, 512–1024 записей. **FSM входного протокола распознаёт только два типа команд:**

- `SET Rn, value` — записать значение в регистр;
- `EXECUTE ID` — запустить микропрограмму с заданным ID.

FSM собирает полную команду из FIFO и передаёт её микрокоманде `NEXT`. Пока выполняется микропрограмма (`FILL`, `COPY`, ...), FSM продолжает принимать байты в FIFO, но `NEXT` не исполняет их до возврата в `MAIN`.

Флаг `FULL` в статусе означает, что FIFO полностью забито. Флаг `FREE` — что ни одной записи нет. Флаг `READY` — что половина ячеек FIFO свободна.

### 3.3 Ядро

Микропрограммный автомат типа «маленький процессор»:

- **Регистровый файл** — 32 слова по 24 бита (BRAM, один порт чтения, один порт записи, зарегистрированный выход).
- **Внутренние регистры АЛУ** — `SRC1`, `SRC2`, `DST` (по 24 бита), плюс `FLAGS`.
- **АЛУ + DSP:** сложение, вычитание, сдвиги, сравнение, умножение 12×12.
- **Память микрокода** — 256–512 слов, загружается процессором при старте.
- **Счётчики и переходы:** условия по Z и N.

Главный цикл:

```
MAIN:
    NEXT
    JP MAIN

FILL:
    ; ...
    JP MAIN

COPY:
    ; ...
    JP MAIN
```

### 3.4 Конвертер координат в адрес

Единственная точка, где вообще появляется адрес. Для линейного индекса `idx = y*stride + x`:

```
4 bpp:  слово = base + idx>>2,   пиксель в слове = idx[1:0]
8 bpp:  слово = base + idx>>1,   пиксель в слове = idx[0]
```

Умножение на каждый пиксель нужно только для аффинного режима и линий. Для прямоугольников микрокод считает индекс один раз на строку, а дальше делает `idx++`.

### 3.5 Буферы слова

- **Буфер источника (`SW`):** держит последнее прочитанное слово.
- **Буфер приёмника (`DW`):** держит слово, в котором меняем пиксели. Флаг «грязное».

Чтение следующего слова запускается заранее.

### 3.6 Комбайнер

Узкий блок на пути данных. В 4 bpp работает младшая тетрада, остальное маскируется. LUT не используется: в 8 bpp она слишком велика.

### 3.7 Источник: форматы 1, 4, 8 bpp

| Формат | Читаем | Пиксель |
| --- | --- | --- |
| 8 bpp | байт | байт целиком |
| 4 bpp | тетрада | 4 бита |
| 1 bpp | бит | `бит ? FG : BG`, BG может быть «прозрачным» |

Stencil — не отдельное устройство, а способ интерпретации слова.

### 3.8 Клиппинг

Четыре регистра `CX0`, `CY0`, `CX1`, `CY1`. Клиппинг по Y — проверка перед циклом, по X — один раз на строку, в аффинном режиме — на пиксель.

### 3.9 Видеоконтроллер и палитра

Видеоконтроллер читает пакетами из памяти и отдаёт пиксели на палитру. Палитра лежит в 8-битном домене. Развёртка имеет **высший приоритет** в арбитре памяти.

## 4. Команды входного протокола

Формат: `SET Rn, value` и `EXECUTE ID`. Размер команды:

- `SET` — 3 байта (опкод + 16-бит значение);
- `EXECUTE` — 2 байта (опкод + 8-бит ID).

FSM собирает полную команду из FIFO и передаёт её `NEXT`. `NEXT` выполняет её за один такт:

- `SET` — запись в регистровый файл;
- `EXECUTE` — переход на адрес микропрограммы `ID`.

## 6. Бюджет

| Параметр | Оценка |
| --- | --- |
| Пропускная способность памяти | около 27 МБ/с |
| Развёртка 640×480×4 bpp | около 9,2 МБ/с |
| Остаётся ядру | 15–18 МБ/с |
| Z80 без помощи | 0,1–0,2 Мпикс/с |
| Весь экран 307 тыс. пикселей | порядка 25–30 мс |

Точное число тактов на пиксель зависит от плотности параллельных микрокоманд. Реальную цифру получим после первой реализации микрокода.

## 7. Что мы осознанно не делаем

- Аппаратный скроллинг и page flip как обязательная вещь.
- LUT цвет×цвет.
- Форматы 2 и 3 bpp.
- Третий источник (заменяется двумя проходами через скрытую страницу).

## Принятые решения

- **Регистровый файл ядра:** 32 слова, один порт чтения, один порт записи.
- **Внутренние регистры АЛУ:** `SRC1`, `SRC2`, `DST`, `FLAGS`.
- **Входной протокол:** FSM распознаёт только `SET` и `EXECUTE`. Микрокоманда `NEXT` обрабатывает их за один такт.
- **Микрокод в RAM (BRAM), не в ROM.**
- **Порядок пикселей:** в байте первым (левым) идёт старшая тетрада.
- **Прозрачность:** цвет 0 источника никогда не пишется.
- **Комбайнер в два уровня.** Базовый: copy, AND, OR, XOR, сложение и вычитание с насыщением.
- **Запуск:** `EXECUTE ID` через `NEXT`.
- **Переполнение FIFO:** шина просто не выдаёт ACK, пока в FIFO нет места.
- **Режим 8 bpp:** только 320×200.

## 8. Открытые вопросы

1. **Порядок байт в 16-битном слове.**
2. **Чтение-модификация-запись.** Читаем ли байт перед записью в 4 bpp?
3. **Заливка по целому слову** как отдельная ветка микрокода.
4. **Точная ширина микрослова** после проектирования всех управляющих сигналов.
5. **Размер палитры** в режиме 4 bpp и 8 bpp.
6. **Задержка `MUL`** на целевой FPGA.
