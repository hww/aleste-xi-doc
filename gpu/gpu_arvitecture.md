## 0. Общие положения

| Параметр | Решение |
|---|---|
| ОЗУ системы | **16 МБ** |
| Режимы | **2:** 8bpp/320×200 (256 цветов + модификаторы палитры), 4bpp/640×200 (16 цветов, текст/UI) |
| Максимум системы | 320×200×8bpp **или** 640×200×4bpp — оба дают **64 КБ на буфер** |
| Буферы | **2 × 64 КБ = 128 КБ** (двойная буферизация) |
| «Старший адрес» | **байт** для видеоконтроллера: бит 0 — буфер A/B, бит 1 — режим |
| Доступ CPU к буферу | **порты + DMA/display list** (CPU не адресует 64 КБ напрямую) |
| Шрифты/спрайты | **в ОЗУ** (16 МБ), адресный генератор читает оттуда |
| Приоритет функционала | спрайты, тайлы, текст, фон, эффекты |

## 1. Адресный генератор

### 1.1 Состав
- **2 генератора:** источник (src) и приёмник (dst). У каждого — свой набор параметров.
- **Память внутри генератора:** регистры лежат друг за другом. **Теневые регистры** читаемы (те, что использовались в момент вычисления; результат записан в память).
- **Процессор может прочитать** вычисленный адрес и маску (из регистров или теневых) — для отладки/драйвера.

### 1.2 Параметры каждого генератора
- **Адрес** (старший байт + младшие; откуда берёт: ОЗУ).
- **Модуло** (шаг строки).
- **Инкремент** (шаг внутри строки / между строками).
- **Флаги направления:** вперёд/назад, справа налево/слева направо.

### 1.3 Режимы
- **Прямоугольник:** инкремент по X, по достижении ширины — прибавление модуло, сброс X.
- **Источник — непрерывный буфер** (шрифт/спрайты в ОЗУ) → в квадратики буфера.
- **Диагональ / линии — НЕ его задача** (см. §4).

### 1.4 Дробная часть (фиксированная точка)
- **6 бит дробной части** внутри аккумулятора.
- **Процессор пишет 16 бит** (`inc_x`, `inc_y`: 10 целых + 6 дробных) — **2 байта**, не 18/24.
- **FPGA складывает с переносом** (сумматор + компаратор) — без тригонометрии.
- **Прямоугольники (Phase 1):** дробная = 0.
- **Масштаб/поворот (Phase 2):** 6 бит достаточно для спрайтов ≤ 32×32 (ошибка ≤ 0.5 пикселя, не видна).
- **Спрайты 64×64+:** 6 бит на границе; если понадобится — 8–10 бит, не ломая архитектуру.

### 1.5 Таблица углов/масштаба
- **У процессора** (в ОЗУ/ROM), **не в FPGA**.
- Вход: угол (дискретный, 6–12 позиций) + размер спрайта (8×8, 16×16, 32×32).
- Выход: `inc_x`, `inc_y` (16 бит каждый).
- Размер: **~144 байта** (крошечная).
- FPGA получает готовый `inc` и складывает — таблицу не хранит.

### 1.6 Работа
- **По очереди**, как DSP, компактно: выбрать адрес генератора → модуло → прибавить → и т.д.

### 1.7 Открыто
- Что именно в теневых регистрах (только результат последнего вычисления или вся цепочка).
- Интерфейс «по очереди»: select+data или два набора.

## 2. Преобразователь форматов

### 2.1 Назначение
Преобразует данные между компактным форматом (монохром, 1bpp) и форматом буфера (8bpp/4bpp), **в обе стороны**.

### 2.2 Прямое (чтение)
- Вход: компактный формат (например, монохромный байт = 8 пикселей × 1 бит).
- Выход: формат буфера (8 пикселей × 4 бита = 32 бита; или × 8 бит = 64 бита).
- Применение: шрифт/спрайт компактно → в буфер в формате буфера.

### 2.3 Обратное (запись)
- Вход: данные из буфера.
- Выход: «абстрактное» — **не для монохрома**, а для **сдвига пикселей** (пиксель 1 → пиксель 2 со сдвигом).
- Применение: копирование со сдвигом (тетрады меняются местами).

### 2.4 Сдвиг и аккумулятор
- Видеоконтроллер **16-битный**, 2 или 4 точки, аккумулятор вдвое больше бит.
- **4bpp-копирование:** два байта → 32-битный аккумулятор (8 пикселей × 4 бита) → сдвиг → маска → запись. **Оптимизация предпочтительнее**, чем по пикселям (иначе производительность падает вдвое).
- **Ключевой вопрос:** произвольный сдвиг или **swap nibbles** достаточно? (Вы склоняетесь к swap nibbles — произвольного сдвига нет.)

### 2.5 Открыто
- Произвольный сдвиг или swap nibbles.
- Аккумулятор: 8/16/32 бита.

## 3. Комбайнер

### 3.1 Назначение
Математические и логические операции над пикселями с масками.

### 3.2 Режимы
- **Константный цвет** (заливка).
- **Прозрачность** (color-key, например нулевой цвет).
- **Логические:** COPY, AND, OR, XOR, NOT. *(уточнить по документам)*
- **Арифметические:** ADD, SUB с **сатурацией** или **зацикливанием**. *(уточнить)*
- **Маски:** произвольная битовая, маска источника. *(уточнить)*

### 3.3 Свойства
- **Регистры только на запись** — читать не надо.
- **Не конвертирует пиксели** (это преобразователь форматов).
- **Точка = комбайнер width=1** (быстрый путь, 2–3 цикла).

### 3.4 Открыто
- Полный список операций (жду документы).
- Маски: какие именно, как задаются.
- Прозрачность: color-key, tolerance.

## 4. Линии — не в железе

**Решение:** аппаратное рисование линий **не поддерживается**.

**Обоснование:**
- SNES, Sega Genesis, Neo Geo, аркадные автоматы — **не делали аппаратных линий**.
- Линии не нужны для игр (спрайты, тайлы, текст, фон, эффекты — вот что нужно).
- Линии — для графиков/визуализации, не для игровой машинки.

**Как рисуются:** процессором через точки (Bresenham, error term, **порог `dx/2`** — сдвиг посередине). Комбайнер (width=1) + АГ обеспечивают достаточную скорость для редких линий.

**Отдельный генератор линий:** **нет**. Если Phase 2 покажет необходимость — отдельный генератор (Bresenham в железе), не через АГ.

## 5. Палитра

- **256×12 SRAM** (отдельно от акселератора, на scanout).
- `b = f(a)` — LUT, **не комбайнер**.
- 8bpp: `a` = 8 бит = `A2:A1` (модификаторы × цвета); `f` покрывает все комбинации.
- 4bpp: `a` = 4 бита = 16 индексов; `f` использует 16 записей, **без модификаторов** (для текста тривиально).
- «Полупрозрачность/свет/тень» — **комбинация** комбайнера (формирует `a`) и палитры (даёт `b`).
- **Открыто:** разбиение `A2:A1` в 8bpp (4+4 / 2+6 / 3+5); 4bpp — те же 16 цветов, что `A1`, или отдельный банк.

---

## 6. Видеоконтроллер и буферы

- «Старший адрес» — байт: бит 0 — A/B, бит 1 — режим.
- Драйвер рисует в «рабочий» буфер, видеоконтроллер читает «отображаемый», FLIP по vblank.
- **2 буфера достаточно** (переключение режимов редкое, перерисовка при смене). 4 буфера (2+2) — возможны (16 МБ), но **не нужны** (KISS).
- **Открыто:** частота кадров, vblank-прерывание, как текст соотносится с графикой (отдельный экран / 40 колонок в 320).
