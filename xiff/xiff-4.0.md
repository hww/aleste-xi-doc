# XIFF v4.0 — Спецификация интерфейсного фреймворка Xi Aleste

Использование идиоматики Си (`arg`, `const`, `*`, `[]`) — это лучший способ сделать инструмент «вневременным». Программист, знающий Си и ASM, поймет такой мета-язык без справочника.

Ниже представлена **Спецификация XIFF v4.0 (Final Draft)**. Она объединяет вашу изначальную идею с нашими наработками по типизации, префиксам и автоматизации.


## 1. Концепция именования и вызовов

XIFF опирается на систему префиксов в ASM для автоматизации решений:

* `_имя` — Функция совместима с Си (Fastcall или стек). XIFF только декларирует `extern`.
* `__имя` — Чистая ASM-функция. XIFF генерирует **Naked-враппер** в `_wrap.asm` для связи с Си.
* **Default Behavior**: Все функции считаются `naked` (программист сам управляет стеком/регистрами). Если сигнатура позволяет (один аргумент до 16 бит), XIFF автоматически помечает функцию как `__z88dk_fastcall`.

## 2. Грамматика аннотаций

### 2.1. Модуль и Файлы

Директивы экспорта задают контекст всего файла.

```asm
;; XIFF:export h "include/video.h"
;; XIFF:export inc "inc/video.inc"
;; XIFF:export wrap "src/video_wrap.asm"
;; XIFF:section "CODE_DRIVER"           -- Секция для кода
;; XIFF:align 256                       -- Выравнивание текущего блока

```

### 2.2. Константы и Перечисления

XIFF ищет `public` или `defc` рядом с аннотацией.

```asm
;; XIFF:const -- Ширина экрана
SCREEN_WIDTH: defc 320 

;; XIFF:enum Mode :type uint8_t
public _MODE_0, _MODE_1, _MODE_2
_MODE_0: defc 0
_MODE_1: defc 1

```

### 2.3. Структуры и Данные

Используется синтаксис массивов и указателей Си.

```asm
;; XIFF:struct Palette
public _pal_data
_pal_data:
_colors:  ds 32 ;; XIFF:field uint16_t[16] -- Массив цветов
_active:  db 0  ;; XIFF:field bool          -- Флаг активности
_name:    dw 0  ;; XIFF:field const char* -- Указатель на имя

```

### 2.4. Функции и Методы

Самый мощный блок. Поддерживает регистровую привязку и семантику флагов.

```asm
;; XIFF:func set_pixel
;;   :arg uint8_t  @h x      -- Координата X
;;   :arg uint8_t  @l y      -- Координата Y
;;   :arg uint16_t @de color -- Цвет (16-бит)
;;   :res bool     @c :invert -- Возврат успеха через Carry (0=Success)
public __set_pixel
__set_pixel:
    ; ... ASM реализация ...
    ret

```

## 3. Типы данных и атрибуты (Идиоматика Си)

| Тип в XIFF | Соответствие в Си | Регистры Z80 (рекомендуемые) |
| --- | --- | --- |
| `uint8_t`, `int8_t` | `unsigned char`, `char` | `A`, `B`, `C`, `H`, `L` |
| `uint16_t`, `int16_t` | `unsigned int`, `int` | `HL`, `DE`, `BC` |
| `void*`, `type*` | `void*`, `type*` | `HL`, `IX`, `IY` |
| `const type*` | `const type*` | `HL` |
| `bool` | `bool` (из `stdbool.h`) | `f` (флаги Z, C) |
| `type[N]` | `type name[N]` | (адрес начала в `HL`) |

**Специальные атрибуты:**

* `:invert` — Инверсия логики флага (для `bool`).
* `:expand-sign` — Автоматическое `ex de, hl` или `ld h, 0` при несовпадении размеров.
* `:naked` — Явное указание, что враппер не должен трогать регистры, кроме аргументов.

## 4. Драйверы и VTable (Aleste Special)

XIFF следит за целостностью системных таблиц.

```asm
;; XIFF:vtable System :size 64
public __sys_vtable
__sys_vtable:
    jp _sys_init      ;; XIFF:method init
    jp _sys_detect    ;; XIFF:method detect :res bool @c :invert
    ds 58             ;; Автозаполнение до 64 байт, если нужно

```

## 5. Логика генерации (Idempotency)

Генератор работает по принципу **"Smart Merge"**:

1. Читает целевой файл (например, `.h`).
2. Ищет блоки `;; XIFF:start <source.asm>`.
3. Если находит — заменяет содержимое внутри.
4. Если не находит — дописывает в конец файла.
5. Пользовательский код вне блоков `start/end` **никогда не удаляется**.

---

### Почему это сработает:

1. **Лаконичность**: Мы не пишем `param`, мы пишем `arg`. Мы не придумываем типы, мы берем их из `stdint.h`.
2. **Автоматизация**: Если вы написали `__draw(uint8_t @a)`, XIFF сам поймет, что для Си это `fastcall` (аргумент в L), и сгенерирует `ld a, l` внутри враппера.
3. **Безопасность**: Валидатор XIFF проверит, что вы не пытаетесь засунуть `uint16_t` в 8-битный регистр `A`.
